# 实验与数据工作流程

[English](WORKFLOW.md) · [项目首页](../README.zh-CN.md)

## 1. 建立实验记录

采集前填写[方案记录表](PROTOCOL_TEMPLATE.md)：动物编号、组别、性别/品系、实验单位、测试足及足底/足背、纤维丝套件、干预和测量安排。同时说明测试者、分析者、随机化及盲法的实施方式。

仓库默认值不构成获批实验方案。适应时间、刺激保持时间、刺激间隔、阳性标准、停止规则、最大力值与测量频率，应以本实验书面方案为准。记录实际钟点，便于复核测量频率和累计刺激暴露。

## 2. 逐次采集观察

按首页说明通过本地服务打开 `app/von_frey_entry.html`，填写方案编号、操作者、设备/套件、日期和实际起点力值，并将时间点调整为实验预定安排。

每只动物、每个时间点保留完整序列。面板约定 `O` 为无阳性反应，`X` 为阳性反应。up-down 规则由上一次反应决定下一根纤维丝：`O` 升一档，`X` 降一档。

有条件时保留每次实际力值，尤其是接近套件边界的记录。边界夹紧后，末次力值未必能唯一反推起点；已有真实起点不得未经核实就被倒推值替换。

## 3. 复核疑问，保留真实观察

核查动物编号重复、字段缺失、起点不在套件内、时间点标签、全同字符序列与边界夹紧。对照原始记录更正，并说明修改原因。

面板还保留本地项目的趋势提示。这些提示用于提醒复核，不能证明记录错误，也不能证明干预必须有效。核实后的阴性结果应保留；“确认原始记录无误”与“修正录入错误”应在审计中区分。

## 4. 导出参考计算输入

通过面板导出网站输入 CSV，或在模拟长表上运行 `tools/prepare_website_input.py`。外部计算器接收：

```text
ID, Final Filament, XO Pattern
```

`Final Filament` 是**最后一个已记录反应对应的实际刺激力值**，区别于起点，也区别于末次反应之后“下一步可能使用”的力值。

现有项目的参考流程使用外部计算器 **Force + Exact**，并提供实验使用的完整、有序纤维丝列表。保留输入文件、档位设置、算法选项和网站原始输出。全同字符与夹紧序列必须明确复核，不能自动解释为普通点估计。

录入面板不会自动向外部计算器发送数据，上传导出的 CSV 需要单独操作。演示外部服务时使用模拟或适当去标识化的输入。

## 5. 核对并确定结果版本

导入网站原始结果 CSV，核对动物与时间点 ID，查看网站值和面板预览的差异。保留原始结果文件与计算配置。

本项目现行口径选择导入的 Force + Exact 输出作为最终报告来源；厂商手柄号、固定 σ 的本地预览用于录入反馈。两种计算口径不能未经预定说明就混成一个终点，应记录结果来源。

全 `X` 或全 `O` 序列需保留删失方向和末次实际力值。原面板可能按项目约定显示一个末次力值数字，但它仍属于删失观测；统计处理应明确规定，避免默认为普通点估计。

## 6. 分析与归档

保持动物、组别与时间点的对应。纵向实验以动物为实验单位，重复刺激和多个时间点不是新增独立动物。按预定方案处理重复测量、缺失和删失。本仓库不声称某项药物有效，也未提供已完成的统计比较。

归档完整序列、起点与末次力值、套件定义、操作者与时间、疑问处理、网站原始输入/输出、长表和含审计的 JSON；后续修正保留日期版本。

加密快照用于所有者恢复原始科研文件；浏览器草稿与公开模拟示例各有用途，不能替代实验归档。
