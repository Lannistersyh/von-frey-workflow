时间点结构

这里管的是表头的列（时间点），不是动物的分组。
· 造模前 / 造模后 是固定列，不能删。
· 「给药后」这类时间点组用来把若干时间点并到一个横跨表头下；组内时间点（默认 0.5/1/1.5/2/3/4h）可 加 / 删 / 重命名。
· 组可以整个 删除本组（会连组内时间点和已录数据一起删）。
· 子时间点的 label 会原样写进网站 CSV 的 ID（如 M1-药效2h）。
· ⚠ 想让动物分成几组（如 Example-A / Example-B / 溶剂组），请在下面②表的 「组别」列 填 —— 填完离开该格，网格会自动出现组分隔条。

Von Frey 数据网格。每行是一只鼠；每个时间点是一格，单元格含 O/X 序列输入框、起点力值下拉、实时 PWT 预览与状态标。

! = 硬错误（格式错 / 序列 <6 位 / 力值非法，会阻止导出）； △ = 软疑问（PWT 超出常规范围，须在下方 Query 面板填理由并勾"已复核"）； – = 必填但未录（安静虚线，不是错误）； 符号 + 文字 + 颜色三重编码，不靠颜色单独传递状态。

3数据校验 + Query 澄清

错误明细（点击条目可跳到那一格）

Query 澄清（超出常规范围的值须填理由）

Query 是医学数据管理的标准做法：超范围但属实的值不应被静默接受，也不应被硬拒； 系统列出疑问，录入者填理由并勾"已复核"，理由随数据一起存档。

4变更审计日志（追加式，不可编辑）

每条记录的创建 / 修改 / 删除都会自动记入审计，含录入人、时间戳、旧值与新值。 审计与数据一起导出，不可单独修改。

6与 DTU/Rigshospitalet 在线工具 联动

在线工具：bioapps.shinyapps.io/von_frey_app（Christensen et al., Eur J Pain 2020）。 网站接受的输入列：ID, Final Filament, XO Pattern（不区分大小写，逗号/分号分隔，欧洲小数点也认）； 输出列：ID, XO Pattern, Final Filament, k-value, delta-value, 50% Threshold。 导入后每格 PWT 旁会显示⇆ 网站值（斜体绿），与本工具 MLE 派生值并列便于对照。

ID 编码约定

与 exports/*_von_Frey_results.csv 完全一致： <药物前缀>-<动物>-<时间点标签>，例如 DEMO-001-基础值、DEMO-001-药效0.5h。 ① 节里设 ID 前缀；时间点标签沿用本面板时间点的 label（如 造模前→基础值、造模后→造模后、给药后→药效0.5h）。
